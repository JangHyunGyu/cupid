# Loading and public-build improvements, 2026-10-16

First delivery covers the agreed priority items: selected-language JSON loading,
public build boundaries, and resilient gallery script loading.

## Translation loading

- Every language loads its own four JSON files per day, with the existing
  four-request concurrency limit, five-attempt file retry and per-day deduplication.
- All four target files must succeed before the day is committed. Failed days
  remain retryable and never expose mixed English/target-language content.
- Translation query versions are generated by sync-build-metadata.cjs from
  config/project.json, including build-check verification.
- All eight complete merged translation datasets equal the pre-change baseline.
- For es/ja/fr/de/pt/zh, measured full-story JSON requests decrease from 40 to 20.
  Korean and English remain at 20. Removed English source payload totals 775,776
  uncompressed bytes per full story; actual network savings depend on compression
  and cache state.

## Public build

- Node-only deepseek_api.js and model_adapters are excluded from dist.
- Asset types are restricted to runtime scripts, scenario modules, localized day
  JSON, stylesheets, fonts, images and audio. Translation extractors, all_nodes.txt
  and work-document Markdown are excluded. The distributed font license remains.
- Build regression checks reject internal files and verify all HTML asset
  references and all 160 translation files are present.
- Source tools remain available in the repository; this change only restricts
  deployment output.

## Gallery loading

- Managed sequential script insertion replaces parser-time document.write calls.
- Failed dependencies receive at most three attempts, preserving execution order
  and preventing dependent modules from running before recovery.
- One automatic page refresh is allowed per unresolved failure episode. Persistent
  failure then shows the existing localized error overlay and retry button.
- DOM readiness and affinity migration both finish before gallery initialization;
  scripts loaded after DOMContentLoaded initialize correctly. Game pages do not
  initialize the standalone gallery UI.
- Prompt verification executes and awaits the managed loader to check the real
  script insertion order.
